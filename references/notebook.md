# Notebook behavior and portable state

Use immutable IDs for source slides, inserted pages, notes, drawings, and cards. Display order is a separate list of page IDs, not an annotation anchor. Record source checksum or stable source identity, original slide index, image dimensions, transcript, speaker notes when present, and extraction status. Normalize drawing and sticky-note coordinates to slide/page dimensions. Resizing or inserting pages must not move existing annotations to another slide.

Maintain a versioned JSON state including page order, reference contents/attribution, notes, drawings, cards/draft baselines, learning evidence, active page, progress, theme, and sidebar state. Persist changes automatically in local storage with a source-specific key. Show save status and handle storage-quota errors visibly. Large embedded images may exceed browser storage; prefer IndexedDB for binary assets when needed, while still embedding them in portable downloads. A storage failure must not appear as a successful save.

Offer **Download saved HTML**, annotation JSON export/import, and optional **Enable HTML autosave** through a browser-native save picker. Explain that the user chooses a destination and may need to reconnect permission after reopening. Use debounced writes, surface failures, and retain the download fallback. Never promise silent overwriting of the original deck or arbitrary local paths.

A downloaded HTML must contain the current complete state and all added image data, work with empty browser storage, and retain exactly one copy of its UI. Build snapshots from a clean template or carefully remove transient UI before serialization. Escape `<` in embedded JSON to prevent script termination; do not concatenate raw source or pasted HTML into executable markup. Render plain text through textContent; sanitize supported rich text and reject script/event-handler content and unsafe links. Validate imported schema, types, IDs, image types, finite coordinate bounds, and size limits before replacing state. Keep a recoverable pre-import snapshot. Import failure must leave existing work intact.

Use a document ID, revisions and explicit restoration rules to prevent older browser state from resurrecting deleted material. Treat portable snapshots and local edits as revisions of the same notebook. When conflicting newer edits exist, offer a restore choice or recoverable copy rather than silently discarding them. Persist deletion tombstones or equivalent revision information. Do not store only external file paths for pasted images.

Test a real round trip: add a slide note/drawing, insert a reference page with an image and citation, edit/save a card, change page order, download HTML, and reopen with storage cleared or isolated. Confirm source slide numbering, inserted image, annotations, card provenance, learning baseline, and page order survive. Check that deleted content stays deleted. Test malformed imports and a quota/write failure. DOM-only checks do not establish visual quality, clipboard permissions, or file-picker behavior; report the distinction.
